## Schema and architecture decisions

- Exactly one `exercises` application table. Text UUID primary key; all columns
  non-null except catalogue version (null only for custom origin at the model boundary).
  Duplicate labels are allowed; names are not keys. No unused relationships, routines,
  substitution table, settings or history graph is introduced.
- Domain model validates canonical UUIDs, required text, unique nonempty tags and
  origin/version pairs. SQLite enforces primary-key uniqueness and NOT NULL. Tag lists
  use a validated delimiter encoding; enum names are stable schema-v1 tokens. No raw
  metadata CHECK/trigger schema outside Room's exported model is claimed.
- Manual application composition owns one lazy Room/repository instance. ViewModel
  invokes suspend seeding; Compose renders immutable loading/error state and retry.
  Repository reads prepare their own catalogue, so future callers do not depend on Home.
  No main-thread database queries or destructive fallback. KDoc and API overview updated.
- All seed changes are transactional. Custom identity collision aborts and rolls back
  earlier inserts. Existing built-in rows are never replaced, including edited labels
  and archived flags. Future catalogue updates require explicit compatibility policy;
  no update engine/custom editor/history feature is implemented now.
- B-01 had no database, so no version-0 migration exists. v1 is the first future
  migration fixture. Unsupported database-version testing proves the original six rows
  and version remain intact after rejected open; full recovery hardening remains B-07.
- Existing toolchain pins retained, including actual merged AGP 9.5.0 (the B-01 report
  and Development table had described 9.3.1). New stable Room 2.8.5 and KSP 2.3.13.
  Serialization runtime BOM 1.12.0 is justified by the observed app/test mismatch below;
  Kotlin/compiler/serialization compiler plugin remain 2.4.21. Sources and rationale
  are linked in [Development](../DEVELOPMENT.md) and the catalogue document.
