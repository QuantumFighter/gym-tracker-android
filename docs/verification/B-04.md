## Review corrections

The review of `9cf1411` identified two valid non-blocking observations. The original
seed/force-stop/verify test closes its activity and database before force-stop. It
proves cross-process preservation after orderly closure, not abrupt termination
with Room open. The intervening normal launcher uses the normal application DB;
verification injects the isolated fixture into the real app composition. Earlier
phrasing that implied an abrupt-kill demonstration was too broad.

The original test is retained. `scripts/verify_workout_abrupt_kill.py` adds a separate
host-controlled phase: record through Compose, wait for the actual Set saved UI,
capture the committed synthetic snapshot, assert Room remains open, and signal the
host with the live PID. The test then waits without closing anything. The host
checks that PID is alive and the finally/cleanup sentinel is absent, force-stops
the package, confirms PID death and no cleanup, then verifies the original snapshot
and command idempotency in a fresh process through Home → Resume workout. This
uses an isolated DB and actual application composition, not the production launcher's
default DB. It proves acknowledged-set survival with no orderly close; it does not
claim a kill inside an SQLite transaction or zero latency between commit and kill.

A separate Room regression simulates a lost response after commit by throwing at
the caller boundary before delivering success, then retrying the same known command.
The exact original row returns and the row count stays one. This is controlled
lost-reply evidence, not automatic pending-UI-command recovery after process death;
drafts and pending command IDs retain their approved best-effort policy.

Command failures now expose operation-specific text and explicit Retry Start Workout,
Retry Start/Stop Warm-up, Retry Start Rest or Retry Save Set actions. Retrying a set
retains its captured values/UUID; editing or changing exercises clears the stale
retry action. The real-Room Compose regression injects failures for each command,
checks persisted state, removes only its synthetic trigger and clicks the appropriate
retry button. No schema, dependency or later-story workflow changes are introduced.

The executed results below describe the original revision unless identified as the
review correction. Final-head CI evidence is maintained on PR #30.

Independent inspection checked migration SQL against compiler output and confirmed
all seven old table definitions are byte-for-byte equivalent as parsed schema
objects. Transaction review checked that snapshot and active-reference writes share
one transaction; every Save Set lookup, validation, sequence allocation and insert

drift from committed performance. Session-owned foreign keys use RESTRICT; there
is no cascading template relationship. UUIDs identify occurrences and commands;
global recordingOrder preserves cross-exercise interleaving independently of time.

Physical SM-A325F / Android 13, the owner's Galaxy A32. Debug APKs installed in
place. Full Compose/Room workflows ran offline with airplane mode enabled; original
mode 0 was restored after each run. Only named `b04-*` synthetic fixtures were

Self-review covered data/UI boundaries, null/zero/load conventions, immutable
snapshots, concurrent/retried commands, failed saves, navigation, migration
preservation, source scope and disclosure of unexecuted qualification work.

- Unsaved drafts are best-effort and can be lost after process death. Every saved
  row is durable; the app never claims a draft was saved merely because it was shown.
- Timers use persisted monotonic anchors on the same boot. Reboot uncertainty,
  wall-clock reconciliation, full-screen timing, automatic rest policies and alerts
  remain B-06. Rest expiry has no automatic workflow action. No reboot qualification
  is claimed. The recording table remains exact independently of timer recovery.
- Recorded sets are free entries attached to immutable exercise occurrences;
  prescriptions are retained separately. Automatic prescription matching and
  superset round/group logic are not implemented.
- Active sessions cannot yet finish or abandon through the UI. Exercise completion,
  warm-down, finalisation, history and cursor advancement remain B-05. Starting again
  correctly resumes the existing active session.
- Failure tests inject SQLite errors; they do not claim physical disk-full or
  power-loss qualification. Process-death evidence covers committed rows; exhaustive
  kill timing around every transaction instruction remains later hardening.
- Full TalkBack/200%-font qualification, API 37 device qualification, and 10,000-set
  performance measurement are not claimed. No progression, exports, account/cloud
  functionality, new dependencies or additional modules were introduced.
- Owner review and all four final-head CI checks are merge gates. Do not merge
  automatically or begin B-05.
